# M3 실행 시스템 — 규모별 패턴

## 핵심 프레임워크
- **Grove OKR:** 목표(정성) + 핵심결과(정량). 분기 단위 정렬. "관리자의 산출 = 팀의 산출."
- **Drucker MBO:** 공유 목표 정렬의 원형. OKR의 조상.
- **RACI:** Responsible(실행)·Accountable(최종책임)·Consulted(자문)·Informed(통보).
- **운영 케이던스 (Harnish):** 일간 허들(5분)→주간 회의→월간 리뷰→분기 전략.
- **핵심 원리:** 실행 시스템 = 목표 정렬(OKR) × 의사결정 프로토콜(RACI) × 회의 아키텍처(케이던스).

---

## 규모별 패턴

### S1 (1-5명)
- **목표 정렬:** 공식 OKR 불필요. 매일 대화가 정렬. "우리 이번 주에 뭐 하지?"
- **의사결정:** 구두 합의. 프로토콜 불필요.
- **회의:** 비공식 수시. 별도 구조 불필요.
- **성공 패턴:** 빠른 피드백 루프 + 전원 맥락 공유 + 즉시 실행.
- **실패 패턴:** "우리는 다 알아" 가정 → 실제로는 정렬 안 됨. 각자 다른 방향.

### S2 (6-15명)
- **목표 정렬:** 분기 목표 3개 이내 명시. 간소화된 OKR 시작.
- **의사결정:** 창업자 최종 결정 + 팀 리드 제안. 비공식이되 명확.
- **회의:** 주간 전체 미팅(30분). 일간 허들(5분) 도입 가능.
- **성공 패턴:** 주간 미팅에서 진척·장애·다음 주 계획 공유. 짧고 규칙적.
- **실패 패턴:** 회의 없음 → 정보 비대칭 축적. 또는 회의 과잉 → 실행 시간 소멸.

### S3 (16-50명)
- **목표 정렬:** OKR 정식 도입. 전사 OKR→팀 OKR 연계. 분기 리뷰.
- **의사결정:** 팀 리드에게 위임 시작. "무엇을" 결정은 상위, "어떻게"는 팀.
- **회의:** 일간 허들(팀별) + 주간 전체 + 월간 올핸즈. 회의 목적 분류(결정/토론/공유) 시작.
- **성공 패턴:** OKR로 정렬 + 팀 리드 위임 + 케이던스 정착. Grove 1:1 도입.
- **실패 패턴:** OKR 도입했으나 리뷰 안 함("분기 초에 쓰고 잊음"). 또는 모든 결정이 여전히 창업자.

### S4 (51-150명)
- **목표 정렬:** OKR cascade (전사→부문→팀). cross-functional OKR.
- **의사결정:** RACI 도입. 의사결정 권한 명시적 문서화. "이 결정의 A는 누구?"
- **회의:** 3단 케이던스(주간/월간/분기) + 경영회의 + 의사결정 회의 분리.
- **성공 패턴:** RACI 작동 + 경영회의에서 전략 정렬 + 팀 자율성 보장. "disagree and commit."
- **실패 패턴:** RACI 없음 → 모든 결정이 상부 대기. 또는 RACI 과잉 → 매트릭스 안에서 아무도 결정 못함.

### S5 (151-500명)
- **목표 정렬:** OKR + 전사 대시보드. 부문 간 의존성 관리. 분기 전략 세션.
- **의사결정:** 사업부 내 자율 결정 + 전사 거버넌스. 의사결정 속도 모니터링.
- **회의:** 다층 케이던스. 사업부별 + 전사. 불필요한 회의 정리("이 회의 왜 하지?").
- **성공 패턴:** 운영 리듬이 자동으로 돌아감. 리더는 "시스템 설계자"로 역할 전환.
- **실패 패턴:** 회의 폭발. "회의 때문에 일할 시간이 없다." 또는 사업부 간 OKR 충돌.

### S6 (500+명)
- **목표 정렬:** 전사 전략 프레임워크(BSC/OKR hybrid). 다년도 로드맵 + 분기 실행.
- **의사결정:** 이사회-경영진-부문-팀 4단 거버넌스. 의사결정 프레임워크 표준화.
- **회의:** 기업 수준 거버넌스 + 사업부 자율 운영. 회의 효과성 측정.
- **성공 패턴:** "운영 OS"가 작동. 개인 영웅이 아니라 시스템이 결과를 만듦.
- **실패 패턴:** 관료화→혁신 사망. 또는 전략-실행 단절(실패패턴 #1).
