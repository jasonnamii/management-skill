# M1 조직설계 — 규모별 패턴

## 핵심 프레임워크
- **Mintzberg 5유형:** Simple → Machine → Professional → Divisional → Adhocracy
- **McKinsey 7S:** Strategy-Structure-Systems(Hard) + Style-Staff-Skills-Shared Values(Soft)
- **핵심 원리:** 조직마다 다른 구조가 필요. 규모·전략·환경에 따라 최적 구조가 달라짐.

---

## 규모별 패턴

### S1 (1-5명)
- **구조:** 구조 없음. 전원이 모든 일. 창업자가 조직 자체.
- **의사결정:** 전원 합의. 별도 프로토콜 불필요.
- **성공 패턴:** 역할보다 문제 해결 중심. 누가 뭘 하든 결과만.
- **실패 패턴:** 공동창업자 간 역할 중복 → 갈등. "누가 최종 결정권자인가" 미합의.
- **→ 다음 규모에서 왜 틀린가:** 6명+부터 "모두가 모든 것을 안다" 전제 붕괴.

### S2 (6-15명)
- **구조:** 창업자 중심 flat. 첫 매니저 또는 팀 리드 등장.
- **의사결정:** 창업자+핵심 1-2명이 대부분 결정. 나머지는 실행.
- **성공 패턴:** 명확한 1인 의사결정자 + 소수 전문가 역할 분화 시작.
- **실패 패턴:** "모두가 평등" 고집 → 결정 지연. 또는 창업자 독재 → 인재 이탈.
- **→ 다음 규모에서 왜 틀린가:** 16명+부터 창업자가 모든 사람·업무를 직접 관리 불가.

### S3 (16-50명)
- **구조:** 기능별 분화 시작 (엔지니어링/제품/영업 등). Mintzberg Simple→Machine 전환기.
- **의사결정:** 중간관리자에게 위임 시작. 주간회의 도입.
- **성공 패턴:** 기능별 팀 리드 + 명확한 책임 범위 + 정기 정렬 미팅.
- **실패 패턴:** 창업자가 위임 거부("내가 더 잘 하는데") → 병목. 또는 구조 없이 인원만 증가 → 혼돈.
- **→ 다음 규모에서 왜 틀린가:** 51명+부터 기능별 구조만으로는 cross-functional 조정 불가.

### S4 (51-150명)
- **구조:** 기능별→프로젝트/스쿼드 하이브리드. Mintzberg Machine 또는 Professional.
- **의사결정:** RACI 도입. 의사결정 권한 명시적 설계. 경영회의 체계화.
- **성공 패턴:** 구조화된 보고체계 + cross-functional 정렬 메커니즘 + 의사결정 프로토콜.
- **실패 패턴:** S3 구조 고수("우리는 flat") → 커뮤니케이션 11,000개 관계 → 혼돈. 또는 과도한 계층화 → 관료화.
- **→ 다음 규모에서 왜 틀린가:** 151명+부터 단일 구조 불가. 사업부/제품 단위 분리 필요.

### S5 (151-500명)
- **구조:** 사업부/제품 단위 분리. Mintzberg Divisional. 각 유닛이 미니컴퍼니.
- **의사결정:** 사업부 내 자율 + 본사 조정 기능. 전사 거버넌스 필요.
- **성공 패턴:** 사업부 자율성 + 전사 정렬(OKR cascade) + 공유 서비스(HR/Finance).
- **실패 패턴:** 사업부 간 사일로 → 자원 중복, 내부 경쟁. 또는 본사 과통제 → 자율성 질식.
- **→ 다음 규모에서 왜 틀린가:** 500명+부터 다국적/다제품/다시장 복잡성 → 매트릭스 또는 플랫폼.

### S6 (500+명)
- **구조:** 매트릭스/플랫폼/홀라크라시. Mintzberg Divisional+Adhocracy 하이브리드.
- **의사결정:** 다층 거버넌스. 이사회-경영진-사업부-팀 4단계.
- **성공 패턴:** 명확한 거버넌스 + 플랫폼 공유 인프라 + 사업부 기업가 정신 유지.
- **실패 패턴:** 관료화 → 혁신 사망. 또는 분권 과잉 → 전사 시너지 소멸.
